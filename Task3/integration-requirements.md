# Требования к внешней интеграции «Умный дом»

Партнёр предоставляет два сервиса: интеллектуальный домофон и интеллектуальный шлагбаум. Собственник пользуется ими через текущее мобильное приложение.

## 1. Что меняется в системе

- **smart-home-service** — новый сервис в группе ЖКУ. Приложение обращается к «Умному дому» только через него. Сервис проверяет, что собственник управляет своим домом, и передаёт команды партнёру.
- **smart-home-db** — новая база данных сервиса. Хранит списки доступа и журнал действий.
- **Мобильное приложение** — появляется раздел «Умный дом».

Фото лиц и видео хранит только партнёр. PropDevelopment их у себя не хранит.

## 2. Требования к безопасности

1. Все данные передаются только по защищённому каналу HTTPS.
2. Собственник видит и открывает только домофон и шлагбаум своего дома. Партнёр не получает данные других домов и других управляющих компаний.
3. Перед регистрацией лица собственник даёт согласие на обработку биометрических персональных данных (152-ФЗ).
4. Персональные данные хранятся на серверах в России.
5. Когда квартира продаётся, доступ старого собственника отзывается.
6. Каждое открытие двери и шлагбаума записывается в журнал: кто, когда и какое устройство.
7. Если связь с облаком пропала, устройства продолжают работать с ключом или кодом.

## 3. Протоколы аутентификации и авторизации

| Взаимодействие | Протокол |
|----------------|----------|
| Собственник → мобильное приложение → smart-home-service | OAuth 2.0 / OpenID Connect через текущий Keycloak (auth-service-1). Приложение передаёт в каждом запросе токен доступа (JWT) |
| smart-home-service → платформа партнёра | OAuth 2.0 Client Credentials: у PropDevelopment есть свой идентификатор клиента и секрет для получения токена |
| Платформа партнёра → smart-home-service (события) | Webhook с секретным ключом, который знают только PropDevelopment и партнёр |

**Авторизация:** smart-home-service проверяет по CRM собственников, что пользователь — собственник квартиры в этом доме. Только после этого он отправляет команду партнёру.

## 4. Взаимодействие с партнёром

- PropDevelopment вызывает REST API партнёра: открыть дверь, открыть шлагбаум, изменить список доступа (лица, номера автомобилей).
- Партнёр отправляет события через webhook: вызов в домофон, проход по лицу, проезд по номеру.

**Сценарий «Открытие по звонку»:**

1. Посетитель звонит в домофон.
2. Партнёр отправляет событие в smart-home-service, а сервис — уведомление в приложение.
3. Собственник смотрит видео и нажимает «Открыть».
4. smart-home-service проверяет права и отправляет партнёру команду «открыть».

**Сценарий «Автоматический проезд»:**

1. Собственник добавляет номер автомобиля в приложении.
2. smart-home-service сохраняет номер и передаёт его партнёру.
3. Шлагбаум распознаёт номер и открывается.
